# 1.9.2

## Bugfixes

* timer callbacks are now scheduled against absolute monotonic deadlines instead of decrementing a shared mutable interval, which could double-subtract elapsed time and let a cancelled request timer leave an empty interval at the head of the selector queue, starving timers scheduled by subsequent requests reusing the same connection/selector.
* a timer cancelled while its interval is being dispatched (including a sibling callback sharing the same delay) is now guaranteed never to run, and cancelling a timer is idempotent and scoped to that timer only.
* `Timers#empty?` now only counts live timers, so a selector whose timers were all cancelled is correctly considered empty.
* request timeout callbacks no longer interrupt a later request reusing the same connection once the originating request has finished; the write timeout callback now also bails out when the request already has a finished response.
* the connection-owned idle/ping timer is now explicitly cancelled when the connection is deactivated or force-closed, and its callback is inert if it ever fires after teardown. This keeps connection liveness timers clearly separate from per-request timers.
