# 1.9.2

## Features

### per-execution (local) callbacks on requests

The `:callbacks` plugin callbacks can now also be registered on a `HTTPX::Request`
object, i.e. the one returned by `Session#build_request`:

```ruby
request = http.build_request("GET", "https://example.com")
request.on_response_completed { |res| ... }
response = http.request(request)
```

Registrations declared this way are scoped to the execution of the request (the
upcoming `Session#request` call, including every internal attempt: retries, redirects,
hedging, ...), and are dropped once the execution finishes, successfully or not. The
same applies to `HTTPX::Callbacks#on` with `local: true`.

Reusing the same `Request` object for a subsequent request therefore only triggers the
session-level callbacks (or the ones explicitly registered with `local: false`). Local
callbacks fire in registration order, interleaved with the session-level ones, and are
visible to every internal attempt of the same execution.

## Bugfixes

* a `HTTPX::Request` object can now be sent more than once through `Session#request`
  (its state is rewound for each new execution); the `:retries` and `:cache` plugins also
  re-initialize their per-request state on reuse.
