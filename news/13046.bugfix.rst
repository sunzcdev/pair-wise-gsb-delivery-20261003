Improve detection of recursive `-r`/`-c` includes in requirements files: the check now canonicalizes local paths and URLs against their respective resolution bases (so remote files that reference back to an ancestor URL are caught too), only aborts when a reference returns to a file already open in the current include chain (shared constraint files in a diamond layout are still parsed once per entry point), and the error message reports the full chain of nested references with the file and line number of every hop.
